# PC 本地 Todo 软件项目计划

## 1. 项目目标

开发一款 Windows 本地 Todo 软件，以卡片形式展示任务，支持自定义日期和时间提醒。软件可完全离线使用，任务数据存储在本机，关闭主窗口后可在系统托盘继续运行。

第一版优先保证：记录方便、数据可靠、提醒准时。

### 计划前提

- 目标平台：Windows 10 / Windows 11。
- 开发方式：单人开发。
- 数据模式：本地存储，无需账号或服务器。
- 预计周期：3～4 周，按熟悉前端开发、无需复杂视觉设计估算。
- 当前项目从零搭建。

## 2. 第一版功能范围

| 模块 | 功能 |
| --- | --- |
| 任务管理 | 创建、编辑、完成、删除任务；删除后可撤销 |
| 卡片展示 | 显示标题、内容摘要、截止时间、提醒时间、优先级；支持颜色和置顶 |
| 分类筛选 | 全部、今天、逾期、已完成；支持标签和关键词搜索 |
| 日期时间 | 截止时间与提醒时间分别设置，支持日期和具体时分 |
| 提醒 | 指定时间提醒；提前 5 / 15 / 30 分钟或自定义提前时间；稍后提醒 |
| 本地运行 | 本地保存、系统托盘、可选开机启动 |
| 数据保护 | 自动备份、手动导出与恢复 |
| 设置 | 浅色 / 深色主题、提醒声音、关闭窗口后的行为 |

第一版每个任务支持一个提醒。提醒时间可直接指定，也可根据截止时间和提前量计算；修改截止时间时，按提前量设置的提醒同步更新。

以下功能安排在后续版本：

- 重复任务。
- 单任务多次提醒。
- 日历视图。
- 桌面悬浮卡片。
- 跨设备同步。

## 3. 界面与操作设计

主界面采用「左侧筛选栏 + 中间卡片区 + 右侧任务编辑面板」。

### 3.1 筛选栏

- 今天。
- 全部任务。
- 逾期任务。
- 已完成任务。
- 标签分类。

### 3.2 卡片区

- 随窗口宽度调整列数。
- 默认按置顶状态、截止时间排序。
- 显示标题、摘要、截止时间、提醒时间和优先级。
- 提供直接完成任务的按钮。
- 逾期任务使用明确的文字提示，避免仅依赖颜色。
- 点击卡片打开编辑面板。

### 3.3 编辑面板

- 编辑标题、内容、标签、优先级和卡片颜色。
- 集中设置截止时间与提醒时间。
- 支持清除日期或关闭提醒。
- 保存后立即更新对应提醒。

### 3.4 快捷新增

输入标题即可保存，其他信息按需补充。

## 4. 技术方案

推荐采用 **Electron + React + TypeScript + SQLite**。

| 部分 | 方案 | 用途 |
| --- | --- | --- |
| 桌面程序 | Electron | 窗口、托盘、系统通知及应用生命周期管理 |
| 界面 | React + TypeScript | 卡片展示、编辑与筛选交互 |
| 本地数据 | SQLite | 保存任务、标签、设置和提醒记录 |
| 提醒调度 | 桌面后台进程 | 检查提醒时间、触发通知、处理遗漏提醒 |
| 安装交付 | Windows 安装包 | 验证安装、升级、卸载和系统通知 |

该方案适合快速完成第一版，界面开发和桌面功能可以分别推进。

Electron 提供系统通知能力，但 Windows 通知需要验证安装后应用的身份和快捷方式配置，不能只测试开发环境。参考：[Electron 官方通知文档](https://www.electronjs.org/docs/latest/tutorial/notifications)。

若更重视安装体积和运行资源，可评估 Tauri。其官方通知插件的定时调度仅支持移动端，桌面端需要自行实现调度。参考：[Tauri 官方通知说明](https://tauri.app/reference/javascript/notification/)。

### 4.1 模块划分

- **任务模块**：任务增删改查、完成状态、标签与排序。
- **存储模块**：数据库访问、结构迁移、备份和恢复。
- **提醒模块**：时间计算、调度、去重、稍后提醒和遗漏处理。
- **桌面模块**：托盘、窗口、开机启动和通知交互。
- **设置模块**：主题、声音与应用行为偏好。

## 5. 提醒机制

提醒时间必须持久化到数据库，调度由桌面后台进程负责，不依赖界面中的计时器。

| 场景 | 预期行为 |
| --- | --- |
| 主窗口打开 | 到点发出系统通知，同时更新任务状态 |
| 主窗口关闭、托盘运行 | 继续提醒 |
| 编辑或删除任务 | 立即更新或取消对应提醒 |
| 完成任务 | 取消尚未触发的提醒 |
| 重启软件 | 从数据库恢复待触发提醒 |
| 电脑休眠后唤醒 | 检查遗漏提醒，合并提示，避免连续弹窗 |
| 完全退出软件 | 第一版停止提醒，下次启动检查遗漏 |
| 电脑关机 | 下次启动检查遗漏 |

### 5.1 产品规则

- 默认关闭主窗口后留在托盘，第一次关闭时说明这一行为。
- 托盘菜单提供「打开软件」和「退出软件」。
- 明确区分关闭窗口与完全退出。
- 点击通知可打开对应任务。
- 提供完成任务、稍后提醒操作；具体入口在通知验证阶段确定。
- 系统通知被关闭时，在软件内给出恢复通知权限的指引。
- 软件不能在电脑关机期间提醒。

### 5.2 可靠性要求

- 记录提醒状态，防止重复发送。
- 修改任务时间后，使旧提醒失效。
- 启动、唤醒及系统时间变化后重新检查待提醒任务。
- 保存绝对触发时间及必要的时区信息，界面按本地时间展示。
- 多条遗漏提醒合并展示，同时保留查看对应任务的入口。

## 6. 开发排期

| 阶段 | 时间估算 | 工作内容与交付物 |
| --- | --- | --- |
| 需求与提醒验证 | 2～3 天 | 确定界面草图和提醒规则；交付可安装的通知与托盘验证程序 |
| 本地任务与卡片界面 | 4～5 天 | 完成任务增删改查、本地保存、卡片展示、分类和搜索 |
| 提醒功能 | 4～5 天 | 完成时间设置、后台调度、稍后提醒、重启恢复和休眠补提醒 |
| 设置与数据保护 | 3～4 天 | 完成主题、开机启动、备份恢复和异常提示 |
| 测试与打包 | 3～4 天 | 验证完整使用流程，修复问题，交付安装包和使用说明 |

第一阶段先验证 Windows 通知与后台运行，尽早发现提醒方面的技术问题。

## 7. 验收标准

- 断网情况下，任务创建、编辑、筛选和提醒均可使用。
- 重启软件后，任务内容与提醒设置完整保留。
- 软件运行且电脑清醒时，提醒调度目标误差不超过 10 秒；系统通知展示单独验证。
- 关闭主窗口后，托盘中的程序仍能提醒。
- 修改时间、完成任务或删除任务后，不再触发旧提醒。
- 重启或休眠恢复后，遗漏提醒得到处理，同一提醒不重复发送。
- 导出的备份能恢复任务、标签和提醒设置。
- 在真实安装环境中完成通知、托盘及开机启动测试。

## 8. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 开发环境通知正常，安装后异常 | 第一阶段即验证安装后的通知、应用身份和快捷方式配置 |
| 关闭窗口导致提醒停止 | 调度放在后台进程，关闭窗口默认保留托盘运行 |
| 休眠或重启导致遗漏提醒 | 唤醒和启动时扫描数据库，合并展示遗漏提醒 |
| 编辑任务后旧提醒仍触发 | 保存修改时更新提醒记录，发送前再次核验任务状态 |
| 本地数据损坏或误操作 | 自动备份、删除撤销、导出恢复，并验证恢复流程 |
| 功能扩张影响交付 | 固定第一版范围，扩展功能进入后续版本 |

4. 完成备份、设置及外观优化。
5. 完成验收测试并交付安装包。
